# 실제 Discord 서버 테스트 체크리스트

테스트 서버에서 `DISCORD_GUILD_ID`를 지정해 명령어를 등록한 뒤 아래 순서대로 확인합니다.

## 1. 관리자 명령어와 패널

- [ ] 일반 사용자에게 `/내전 세팅`이 기본적으로 보이지 않는다.
- [ ] 일반 사용자가 강제로 호출해도 런타임 권한 검사에서 거절된다.
- [ ] 관리자에게 `/내전 세팅`이 보인다.
- [ ] 빈 카테고리 ID는 모달 자체에서 제출되지 않는다.
- [ ] 잘못된 ID를 입력하면 비공개 오류가 뜬다.
- [ ] 일반 채팅 채널 ID를 입력하면 카테고리가 아니라고 안내한다.
- [ ] 올바른 ID를 입력하면 같은 카테고리에 `👊ㆍ내전-만들기` 채널과 임베드가 생성된다.
- [ ] 코어 임베드가 고정 메시지로 등록되지 않는다.
- [ ] 같은 카테고리에 패널을 다시 만들면 중복 오류가 뜬다.

## 2. 모집 생성 제한

- [ ] 한 사용자가 협곡 모집을 만들 수 있다.
- [ ] 같은 사용자가 협곡 모집을 다시 만들면 거절된다.
- [ ] 같은 사용자가 아람 모집을 추가로 만들 수 있다.
- [ ] 일반 사용자가 예약 모집을 누르면 관리자 전용 오류가 뜬다.
- [ ] 관리자는 예약 모집을 만들 수 있다.
- [ ] 다른 사용자는 자신의 협곡 모집을 별도로 만들 수 있다.
- [ ] 기존 모집 채널을 삭제한 뒤 같은 종류의 모집을 다시 만들 수 있다.
- [ ] 협곡 방을 2개, 아람 방을 1개 만들면 이름이 각각 `협곡대기열🄐`, `협곡대기열🄑`, `아람대기열🄐`가 된다.
- [ ] 협곡/아람 각각 중간 순번의 방을 닫으면 해당 게임의 가장 작은 빈 순번을 재사용한다.
- [ ] 해당 게임의 즉시 모집방을 모두 닫은 뒤 새로 만들면 다시 `🄐`부터 시작한다.
- [ ] 예약 채널 이름이 `⏰ㆍ협곡예약❨MM∕DD❩` 또는 `⏰ㆍ아람예약❨MM∕DD❩` 형식이다.

## 3. 즉시 모집 선택 입력

- [ ] 협곡/아람 버튼을 누르면 시작 시간과 설명을 입력하는 모달이 열린다.
- [ ] 시작 시간 셀렉트에 `10`, `15`, `20`, `30`, `45`, `60`, `90`, `120`분이 표시된다.
- [ ] 시작 시간과 설명을 모두 비워도 기존처럼 시간·설명 없는 모집이 생성된다.
- [ ] 시작 시간만 선택하면 예약 임베드와 같은 Discord 현지 시간 표시가 나온다.
- [ ] 설명만 입력하면 설명이 임베드에 나오고 시간 영역은 표시되지 않는다.
- [ ] 시작 시간과 설명을 함께 입력하면 둘 다 임베드에 표시된다.

## 4. 예약 검증과 현지 시간

- [ ] 게임 종류가 `협곡`/`아람` 셀렉트 메뉴로 표시된다.
- [ ] 타임존이 `PST`/`EST`/`CST`/`MT` 셀렉트 메뉴로 표시된다.
- [ ] 날짜 입력란이 `MM/DD/YYYY` 형식을 검증한다.
- [ ] 날짜·시간 형식이 틀리면 구체적인 오류가 뜬다.
- [ ] 과거 시간을 넣으면 거절된다.
- [ ] `PST`, `EST`, `CST`, `MT`가 각 미국 지역의 서머타임까지 정상 처리된다.
- [ ] 서로 다른 타임존으로 설정된 Discord 클라이언트에서 같은 예약이 각자의 현지 시간으로 보인다.

## 5. 대기열

- [ ] 참가 시 본인 서버 닉네임 멘션이 임베드에 즉시 표시된다.
- [ ] 중복 참가는 거절된다.
- [ ] 도망가기 시 즉시 제거된다.
- [ ] 미참가 상태에서 도망가기는 거절된다.
- [ ] 9명까지는 첫 번째 `현재/10` 명단만 표시된다.
- [ ] 10명이 되면 두 번째 `10/20` 명단이 표시된다.
- [ ] 20명이 되면 세 번째 `대기자` 명단이 표시된다.
- [ ] 21명 이상도 참가할 수 있고 대기자 명단에 선착순으로 표시된다.
- [ ] 앞 순번이 빠지면 기존 대기자가 선착순 그룹으로 올라온다.
- [ ] 봇을 재시작해도 명단과 순서가 유지된다.
- [ ] 협곡 모집 임베드는 초록색, 아람 모집 임베드는 파란색이다.
- [ ] 모집 임베드 최초 생성 시 임베드 밖 채팅 내용으로 `||@here||`가 실제 알림된다.
- [ ] 참가·이탈로 임베드가 갱신되거나 봇을 재시작해도 `@here`가 다시 알림되지 않는다.
- [ ] 관리자와 봇을 제외하면 모집 상위 채널에 직접 메시지를 보낼 수 없다.
- [ ] 모집 임베드에 `💬ㆍ내전 채팅` 쓰레드가 자동 생성되고 일반 사용자가 쓰레드에는 메시지를 보낼 수 있다.

## 6. 올 멘션

- [ ] 대기열이 비어 있으면 사용할 수 없다.
- [ ] 1~10명이면 현재 대기열 인원 전원이 실제 알림 멘션된다.
- [ ] 11명 이상이면 선착순 10명만 실제 알림 멘션된다.
- [ ] 12명일 때 11·12번째 사용자는 멘션되지 않는다.
- [ ] 누가 버튼을 눌렀든 서버 전체 10초 쿨타임이 공유된다.
- [ ] 다른 모집 채널에서도 같은 서버 쿨타임이 적용된다.
- [ ] 올 멘션 메시지가 전송 후 약 14초 뒤 삭제된다.

## 7. 올 소환

- [ ] 모집 생성자·관리자 외 사용자는 거절된다.
- [ ] 0~9명에는 올 소환 버튼이 비활성화되고 서버에서도 실행이 거절된다.
- [ ] 10명이 되면 올 소환 버튼이 활성화된다.
- [ ] 13명일 때는 선착순 10명만 소환 대상이 되고 후순위 3명은 제외된다.
- [ ] 20명이 되면 선착순 20명이 소환 대상이 된다.
- [ ] 22명일 때는 선착순 20명만 소환 대상이 되고 대기자 2명은 제외된다.
- [ ] 모달에 음성 채널 선택 메뉴가 표시되지 않는다.
- [ ] 대상이 고정 음성 채널 `812822837495988244`로 설정된다.
- [ ] 고정 음성 채널이 없거나 일반 음성 채널이 아니면 안내 오류가 뜬다.
- [ ] `전부 소환`을 정확히 입력하지 않으면 실행되지 않는다.
- [ ] 확정된 선착순 10명 또는 20명 중 다른 음성 채널에 접속한 사용자만 이동한다.
- [ ] 실제 이동이 성공한 뒤 버튼이 비활성화되고 다시 사용할 수 없다.
- [ ] 모집 채널에 실행자, 실제 이동된 사용자, 대상 음성 채널이 기록된다.
- [ ] 이동 가능한 사용자가 0명이면 사용 횟수가 소모되지 않는다.

## 8. 삭제와 복구

- [ ] 모집 생성자·관리자만 삭제할 수 있다.
- [ ] 삭제 시 모집 채널이 사라지고 같은 종류를 다시 만들 수 있다.
- [ ] 모집 채널을 Discord에서 수동 삭제해도 DB 상태가 정리된다.
- [ ] 코어 임베드나 대기열 임베드만 수동 삭제하고 봇을 재시작하면 메시지가 복구된다.

## 9. 임베드 사용자 설정

- [ ] `title` 줄을 삭제하거나 `null`, `""`로 설정해도 봇이 정상 실행된다.
- [ ] `footer`를 문자열 또는 `{ text, icon_url }` 객체로 사용할 수 있다.
- [ ] `author`, `thumbnail`, `image`, `fields`, `url`, `timestamp`를 추가할 수 있다.
- [ ] `panel` 또는 `recruitment` 설정 블록 전체를 비워도 상호작용이 실패하지 않는다.
- [ ] `recruitment.queue`를 삭제하면 대기열 필드만 숨겨지고 참가·이탈 기능은 계속 동작한다.
- [ ] 잘못된 이미지 URL이나 색상 값은 해당 항목만 무시하고 봇은 계속 실행된다.
